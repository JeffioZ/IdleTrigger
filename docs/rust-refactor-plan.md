# Rust 重构整体修复方案

本方案合并 [原移植待办及统一问题索引](rust-port-todos.md) 与 2026-09-13 系统审查，
基线 fec35c2051904a60ed5a114782932bb03f7948ce。已开始分批实施，状态与证据见 [修复进展](rust-fix-progress.md)。

结论：保留 Rust + Win32 + GDI+，重点调整状态所有权、配置事务、原生控件生命周期。
不需要再次更换语言/框架，也不应原样复制旧 Go 的全部文件。

## 方案审查结论

| 现有方案的风险 | 调整 |
|---|---|
| UI 待办被当成整个重构的收尾清单 | 纳入保存、调度、空闲监测、FFI、IPC、主题与发布，追踪 R01–R56 |
| 先修绘制，保存仍失败或任务误执行 | 保存事务与无副作用验证入口前置；空白根因定位可先行 |
| 以重绘/延时“缓解”作为完成 | 区分数据、控件绘制和窗口合成，必须验证真实交互 |
| 状态规则和事件都塞进一个队列 | 分开持续状态聚合、事件等待和告警；不默认排队所有系统动作 |
| UI 完成后再补 DPI/键盘/可访问性 | 这些是公共控件契约，首个控件就同时验证 |
| 重写一个通用 UI 框架 | 只抽取实际重复的 EDIT surface、choice、viewport、模态和资源所有权 |
| 一次迁移全部全局状态 | 按工作包替换，经窄接口迁移消费者，始终只有一个权威写入源 |
| 主题写注册表等于修复成功 | 目标、观察状态、应用结果分离，修复设独立实机门槛 |
| 56 个编号对应 56 个零散补丁 | 按共同根因分包，编号用于追踪，避免重复修改 |
| 以“代码已写”关闭待办 | 实现、必要测试、对应 UI/系统验收全部满足后关闭 |

## 需要澄清的证据

- 原清单“保存失败只写日志”不准确：main.rs 的 persist_config 已弹通用警告。
  真实缺陷是返回值未传给编辑器，失败后仍可能关闭、重载，且序列化错误被吞掉。
- 前轮截图使用 GetDC(hwnd)+BitBlt 客户区捕获，不是 PrintWindow，也不是完整桌面捕获。
  空白是现有证据，但尚未完成真实鼠标路径与桌面像素验收；状态文字里的条数也不能替代
  LVM_GETITEMCOUNT、插入返回值的直接检查。
- 原清单“present_control 等价 Go”仅是实现意图，不能当作首帧/遮挡问题已解决。
- 列宽、自动化 tooltips、表头/滚动条主题化在首轮报告中不够独立，现在保留专门验收项。
- Cargo.lock 已提交，属于已完成项，不再计为未完成重构。

## 模块职责

### 配置仓库

拥有注释 TOML、最后有效配置、规则及版本号。编辑生成候选，不直接改变运行态；
检测草稿版本冲突，准备文档并写盘，成功后发布新版本，失败保留旧状态、草稿和窗口。
未编辑坏条目保留原文，单条错误不导致全体规则丢失。

写盘与发布之间不能插入另一个写者；持锁时不弹 MessageBox 或同步调用 UI。
原子替换不是断电耐久性，配置与 state 文件也不宣称跨文件事务。
热加载应用配置版本，不靠反复重启全部后台线程；忽略自身通知但不漏外部修改。

### 规则引擎与有效状态

纯逻辑接收配置、时钟、进程和电池快照，输出聚合状态及事件意图，不直接调用 Win32。
持续状态按全部有效规则重算，规则顺序不改变结果；暂停、电池和互斥统一处理。
旧 runner 已可见 keep-screen 的 OR 聚合、最小 idle-minutes 等规则，应提取成行为测试。

运行器拥有每条规则的基线、等待和去重状态；规则变化按 ID/语义版本失效。
进程快照失败表示未知，不能当作全部进程退出，也不能阻断无进程条件的时间任务。

### 事件与告警

明确到期、等待条件、占用动作槽、倒计时、取消、提交动作、结果的状态转移。
动作携带 rule ID、occurrence、配置版本与告警会话；过期消息不能执行。
唯一生产动作入口检查会话有效性并返回系统 API 结果；预览使用无副作用执行器。

空闲告警与自动任务告警可复用绘制，但取消契约不必相同，文案必须准确。
不承诺跨进程崩溃的 exactly-once：记账和 Windows 系统动作不在同一个事务中。
先遵循旧版防重复策略，明确失败窗口，不自动重试可能已执行的重启。
采用队列前先核对“忙时跳过/等待”的旧契约，避免恢复后意外补执行旧动作。

### 时间和平台边界

本地日历时间用于计划；单调时间用于宽限、等待及经过时间。恢复、时区、DST、时钟跳变分别处理，
测试注入时钟，不通过真实 sleep 等待。进程一次枚举、路径按需解析，说明异步补充。

FFI 优先 SDK 绑定；只围绕资源所有权、返回值和可测试边界封装，不为每个函数做抽象。
保持单 EXE、系统 DLL 运行依赖。

### UI 所有权

UI 线程唯一操作 HWND。窗口拥有草稿、选择、滚动、焦点和自身 DPI。
后台结果带代次；关闭后到达的结果不能写进重用 HWND。
后台不持业务锁同步 SendMessage 给 UI，UI 不等待同一把后台锁。

公共层覆盖 surface+EDIT、列表呈现、choice、模态、tooltip、viewport、主题资源。
优先原地 DPI 布局；必须重建时保存状态、注销旧资源并恢复，普通窗销毁不退出应用。
自绘必须同时满足可访问状态、键盘和文本缩放，不能因原生 BUTTON 类就假定自动支持。

### 主题协调

计划输出目标、平台读取观察状态、应用操作返回结果，UI 读取同一快照。
位置来源、缓存和太阳计算统一，不由面板与引擎分别计算。
IP 异步；恢复、电源、拓扑、计划事件合并，稳定检测有上限和冷却。

COM 修复是否恢复依据旧行为与实机证据。注册表写成功不能代替 DWM 修复验收；
能力不足时如实降级。不恢复已弃用的 GPS 或手动坐标配置。

## 工作包与依赖

顺序表示落地依赖，不表示启用并行代理或允许多个写者同时修改同一模块。

| 包 | 范围 | 前置 | 完成标准 |
|---|---|---|---|
| W0 基线与验证入口 | 旧行为案例、假执行器、诊断隔离；R11/R54 | 无 | 预览/自动测试不执行真实动作，不改用户配置 |
| W1 Win32 高风险边界 | R02/R03/R10/R26 | W0 | 双架构 ABI/错误路径、URL、窗口销毁验证 |
| W2 配置事务 | R01/R17/R18/R38/R45/R46；原差距 3/4/10 | W0 | 保存往返、失败保留、坏条目、注释、旧 state、冲突 |
| W3 状态与事件 | R04–R09/R13–R16/R19/R49–R51 | W2 接口，W0 | 假时钟覆盖聚合、等待、取消、时间跳变和恢复 |
| W4 UI 恢复 | R12/R31–R41/R52/R55，原 UI 清单全部 | W1 生命周期；保存接 W2 | 鼠标/键盘、深浅色、DPI、选择和模态验收 |
| W5 主题完整性 | R20–R25/R27–R30，主题协调 | W1 平台、W3 状态、W4 通知 | 纯计算通过，系统/多屏实测，降级反馈真实 |
| W6 对外入口与发布 | R42–R48/R53/R55/R56、文档 | 消费统一接口 | CLI/IPC、文案、最低系统、双架构与文档 |

W4 的空白定位在 W0 后即可开始，不必等整个后端结束。W1/W2 可以先做小范围确定修复；
W6 中错误退出码等也可提前修，最终接入统一接口。每包自带必要测试，不拖到最后统一补测。

## 空白控件诊断与验收

1. 固定非空任务名、数值/日期 EDIT、多行带表头列表和选中预览。
2. 记录 HWND、父子关系、可见性、尺寸、DPI、样式、z-order、插入返回值与条数。
3. 分别走真实鼠标与 devtools 路径，检查是否创建不同的模态链/first-frame 顺序。
4. 单变量核对 surface 遮挡、WM_SETREDRAW 配对、裁剪/更新区域、cloak/uncloak 与主题重建。
5. 保留失败证据，再验证首次打开、重开、搜索刷新、晚到说明、遮挡恢复、主题/DPI 变化。
6. 客户区捕获、PrintWindow、桌面像素是不同证据，前两者正常不足以判定用户屏幕正常。

不预定“删 surface”或“加延时”方案，也不因某次不复现关闭缺陷。

## 验收矩阵

| 层 | 必须覆盖 |
|---|---|
| 配置 | 空/单/多规则、坏条目、注释、写失败、外部修改/删除、旧配置/state、自写通知 |
| 任务 | 顺序置换、启停删除重启、any/all/none、同名多路径、扫描失败、等待超时、多事件同轮、一次性取消 |
| 时间 | 跨日/周界/闰日、无效日期、启动错过、恢复、前拨回拨、时区/DST、极昼夜 |
| 动作 | 旧 timer、取消/改配置、API 失败、忙槽、预览隔离、零秒与长提醒 |
| UI | 深浅色×中英文，100/125/150/200% DPI，高文本缩放，小工作区，负坐标副屏，真实键鼠/焦点 |
| picker | 失败/空结果/慢说明、筛选保留选择、路径撤销、列宽、滚动保持、关闭后晚结果 |
| 主题 | 首次状态不一致、跨日手动覆盖、电池/AC、位置/网络变化、全屏/演示、拓扑和修复降级 |
| 发布 | fmt/clippy/test、x64/x86 Release、devtools 隔离、最低 Win10 1607/Server 2016 与现代系统、导入表/系统 DLL |

纯逻辑覆盖关键边界，UI 矩阵逐窗验证；不机械地把每个逻辑案例乘以全部环境。
多屏/DPI/语言共同影响的布局需要交叉验收。没有环境就记录未验收，不能填通过。
真实系统动作另安排合适环境，假执行器是日常回归默认入口。

## 完成、删除和开放决定

每项记录修复位置、验证方法/结果、剩余限制。编译通过、注释 parity 或单张截图不足以完成。
新实现接管全部消费者后再删重复计算、错误 FFI、冗余绘制补丁和旧全局写入。
不删除功能、配置或私人辅助材料来降低待办数量。

准确旧版基线、冲突/等待契约、主题修复能力仍待确认。
旧版未明确的 DST、同时到期或失败记账行为，列具体场景和建议后集中询问。
确定缺陷可先修，重构不能顺手改变未决默认行为。
