## 空白问题的因果证据

原代码在创建背景 surface 后立即将它设为底层，接着创建 LISTBOX/ListView/EDIT。
Windows 将新子窗口插入现有兄弟窗口下面，因此创建结束时背景反而位于内容上面。
WS_CLIPSIBLINGS 下，重复 RedrawWindow 不能改变遮挡关系。

新增原生窗口测试明确断言：
1. 创建 surface，再创建内容，父窗第一个子窗口是 surface。
2. 在所有子窗口创建后执行 lower_surfaces，第一个子窗口变为内容。

相同捕获流程修复前显示 131 项却无表头/行，修复后显示表头、名称、说明、勾选框；
任务管理器行和 EDIT cue 文本同时恢复。深浅色均已复核。
这是当前复现路径的确定修复，不声称其他 DPI/显卡环境全部验收。

首轮捕获中深色列表的表头和滚动条仍为浅色；后续专项修复见下文，其他列表/窗口的 R40 验收仍开放。

## 第二轮：复审首批修改并继续 W2/W3

首批完整 diff 复审发现并修正了以下问题，没有直接给出“无问题”结论：

- 等待任务过早写 occurrence，且记录值取真实时钟而非本轮注入日期。
  现在进入等待不记账，触发、跳过或到达截止时间才记录原 occurrence；后续扫描不会重置截止时间。
- 动作槽已占用但 PostMessage 失败时没有回滚。现在失败释放 payload 与 busy；
  无目标 HWND 也按失败处理，避免 Win32 将空 HWND 当成成功投递的线程消息。
- 普通动作窗销毁不能无条件释放由排队事件占用的槽；只释放该窗实际持有的倒计时会话。
- PDH 返回长度增加显式分配边界检查；定位注释纠正为各阶段 5 秒，不能宣称整个请求最多 5 秒。
